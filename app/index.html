How to wire these up

  • Every screen loads app.css + app.js. No build step, no framework — port to your templating as you like.
  • Elements that need live data carry data-api="METHOD /path" naming the endpoint we assumed. Sample values in the HTML show the expected format.
  • Logged-in screens share the shell in kit.html (rail, top bar, phone tab bar). Copy it as-is; the current page highlights itself.
  • States to render server-side: .skel while loading, .empty when there is nothing, .alert--err on failure, aria-invalid="true" + .error on bad fields.
  • JS helpers: toast('msg', 'err'), [data-open="dialogId"], [data-close], [data-nav-toggle].
